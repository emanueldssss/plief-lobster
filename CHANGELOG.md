# Changes

## 3.1.4

Separate the language of the conversation from the language of the code. SKILL.md said only "Work in the user's language", which agents were applying to identifiers as well, so a request written in Portuguese produced `usePreferenciaDeMovimentoReduzido`, `CAMINHOS_DAS_FORMAS` and `FormaDemo` in the source. The new Language section states the two decisions separately: talk to the user in their language, write code in English. It scopes English to identifiers, file names, CSS classes, test names, commit messages and comments, and it deliberately excludes user-facing copy, which follows the product's language, i18n values, and untranslatable domain terms such as `cpf` or `pix`. Editing an existing codebase still matches the convention already in the files rather than mixing two languages.

## 3.1.3

Close the project fingerprint. It was recorded and never verified, because writing the evidence changed the tree it covered. `lobster-fingerprint/v1` makes it recomputable: the run declares the exact scope it fingerprinted, and `verify-v3` rebuilds the digest from the files on disk. The scope may only omit trees another verified hash chain already covers - `artifacts/` by the evidence manifest, `proof/` by the receipt index, plus the receipt itself, whose exclusion is proved by reading the file and matching it against the receipt under verification rather than taken on trust. Anything else yields `LOBSTER_FINGERPRINT_SCOPE_TOO_NARROW`, so a run cannot exclude `src/` to hide a change. The digest is deterministic by construction: entries sorted by UTF-8 bytes rather than `localeCompare`, built from length-delimited fields rather than a JSON serializer, separators normalised, symlinks recorded as leaves and never followed, and the exclusion spec folded into the digest header so a digest cannot be replayed under a wider scope. The algorithm lives in `scripts/lib/fingerprint.mjs` and `scripts/lobster.py` and a test asserts the two agree byte for byte; aligning them exposed a divergence where Node reports a Windows junction as a symbolic link while pathlib reports it as a directory, which is now settled by the reparse tag. The run record is `lobster-runtime/v3`; a `lobster-runtime/v2` run is still readable but reports `LOBSTER_PROJECT_FINGERPRINT_UNVERIFIABLE`. The golden was migrated by real re-execution. `.gitattributes` disables end-of-line conversion, without which a checkout would rewrite the bytes the fingerprint hashes, and `.github/workflows/ci.yml` runs the suite on Linux and Windows; see `tests/CROSS-PLATFORM.md` for when `DELIVERY_READY_CROSS_PLATFORM` may be claimed.

## 3.1.2

Close the path audit. The target root is now resolved exactly once per invocation and threaded down as an explicit `root=` argument: `verify()` previously resolved it four times, so a relative `--project` plus a cwd change between sub-checks made one invocation audit two different projects and merge the findings into one verdict. The three separate containment implementations collapse into `contain()`, which reports why it refused; the Node adapters share `scripts/lib/contain.mjs` and `doctor` fails the core when it is missing. `verify-v3` now validates the runner's own artifact paths for containment, hash freshness and agreement with the evidence manifest — nothing checked them before, which is how the golden came to express run artifacts against the package root while the evidence manifest used the project root. The golden is now root-portable: its recorded paths are project-relative, its unreferenced duplicate `scenario-matrix.json` (which disagreed with the referenced one) is removed, and the run record was regenerated by real execution. `RECORD_VALID` is formalised as the whole-record gate rather than profile validity alone, `STAGE_CONTRACT` is published in every result, and cross-artifact findings are attributed to the stage whose claim they break instead of all landing on `EXECUTION_VERIFIED`.

## 3.1.1

Rebuild path resolution on a single authority. `project_root()` resolves the target root exactly once and raises `ProjectPathError` with the operation and the path; `contained_path()` rejects absolute, drive-prefixed and `..` record paths and confirms containment after resolution. `verify-v3` previously joined record-supplied paths onto the raw `--project` argument, so an absolute path in a dependency-graph node, an evidence-manifest row or the scenario-matrix reference read and hashed a file outside the project and still computed `DELIVERY_READY`; those joins now go through the guard and report `LOBSTER_PATH_ESCAPES_PROJECT`. `browser-runner.mjs` validates every screenshot path before launching a browser and anchors screenshots to the project root instead of the process cwd; a project fingerprint that cannot be computed is an error instead of the string `unknown`, and symlinked directories are recorded as leaves so a link loop cannot recurse forever. `dependency-graph.mjs` records an import resolving outside the project as unresolved instead of emitting an out-of-closure node. Cross-artifact staleness no longer drags unrelated research and craft findings into the execution stage. Filesystem failures name the operation and the path.
